## Applications
- `GET /Applications` — Возвращает список приложений. · коды: 200, 204, 206
  → map<ApplicationResult>
  Метод используется для получения справочника приложений.
Поддерживает диапазон через заголовок `Range`.
            
## Пример запроса:
```text
GET /Applications
Authorization: Bearer <token>
Range: items=1-50
```
            
## Пример успешного ответа (200):
```json
{ "1": { "code": "LIC", "nameRu": "Лицензия" } }
```
            
## Пример успешного ответа (206):
Тело ответа имеет тот же формат, что и для `200`, но содержит только часть диапазона.
            
## Негативные сценарии:
- 401 Unauthorized — отсутствует или некорректен Bearer-токен.
- 403 Forbidden — недостаточно прав `ApplicationList`.
- 204 — справочник приложений пуст.

## Attachments
- `GET /Attachments` — Возвращает список вложений. · коды: 200, 204, 206
  ← query: assetID?:int, taskID?:int, assetTemplateID?:int, attachmentID?:int, isDeleted?:bool → map<RAListResult>
  Поддерживает фильтрацию по связанным сущностям и флагам, а также ограничение результата через заголовок `Range`.
            
## Пример запроса:
```text
GET /attachments?taskID=1001&isDeleted=false
Authorization: Bearer <token>
Range: items=1-50
```
            
## Пример успешного ответа (200):
```json
{
  "123": {
    "id": 123,
    "fileName": "photo.png",
    "description": "Фото для тестов",
    "publicUrl": "https://files.example.com/attachments/123",
    "isUploaded": false,
    "isProtected": false,
    "size": 1024,
    "created": "2026-08-19T10:44:42Z"
  }
}
```
            
## Пример успешного ответа (206):
Тело ответа имеет тот же формат, что и для `200`, но содержит только часть диапазона.
            
## Негативные сценарии:
- 401 Unauthorized — отсутствует или некорректен Bearer-токен.
- 403 Forbidden — недостаточно прав `AttachmentsList`.
- 204 — вложения по указанным критериям не найдены.
- `DELETE /Attachments` — Удаляет несколько вложений. · коды: 202, 500
  ← body: int[]
  Помечает переданные вложения и их связи как удаленные.
            
## Пример запроса:
```text
DELETE /attachments
Authorization: Bearer <token>
```
```json
[101, 102]
```
            
## Пример успешного ответа (202):
(пустой response body)
            
## Негативные сценарии:
- 401 Unauthorized — отсутствует или некорректен Bearer-токен.
- 403 Forbidden — недостаточно прав `AttachmentDelete`.
- 500 — во время удаления произошла внутренняя ошибка.
- `GET /Attachments/content/{container}/{filePath}` — Скачивает файл по временной подписи файлового хранилища. · коды: 200, 500
  ← path: filePath:str, container:str; query: temp_url_sig?:str, temp_url_expires?:int, filename?:str
  Метод доступен без авторизации, так как использует временную подпись файлового сервера.
            
## Пример запроса:
GET /attachments/content/container1/path/to/file.png?temp_url_sig=<sig>&temp_url_expires=1730000000&filename=file.png
            
## Успешный сценарий:
- 200 — бинарное содержимое файла.
            
## Негативные сценарии:
- 500 — внутренняя ошибка при скачивании файла (ошибка во время подготовки/загрузки).
- `GET /Attachments/downloadLink` — Подготавливает данные для скачивания архива вложений по заявкам. · коды: 200, 204, 206, 500
  ← query: taskID?:int, isDeleted?:bool → FSRDownloadLinkResult
  Используется для формирования архива файлов по списку заявок.
В одном запросе поддерживается не более 100 заявок.
            
## Пример запроса:
```text
GET /attachments/downloadLink?taskID=1001&taskID=1002&isDeleted=false
Authorization: Bearer <token>
```
            
## Пример успешного ответа (200):
```json
{
  "downloadUrl": "https://storage.example.com/container/folder.zip",
  "headers": [
    { "name": "X-Auth-Token", "value": "token-example" }
  ],
  "expiresAfter": "2026-08-19T14:32:00Z"
}
```
            
## Негативные сценарии:
- 401 Unauthorized — отсутствует или некорректен Bearer-токен.
- 403 Forbidden — недостаточно прав `AttachmentsList`.
- 204 — для указанных заявок не найдено вложений или не передан ни один `taskID`.
- 500 — внутренняя ошибка при подготовке архива.
- `POST /Attachments/upload/fromBody` — Загружает один файл из тела запроса. · коды: 201, 400
  ← body: FromBodyUploadData → RAUploadResult
  Используется для сценариев, где содержимое файла и метаданные передаются в JSON-теле запроса.
            
## Пример запроса (JSON):
POST /attachments/upload/fromBody
Authorization: Bearer <token>
            
{
  "file": "<base64>",
  "fileName": "photo.png",
  "contentType": "image/png",
  "description": "Фото",
  "isPublic": false,
  "isIgnorePossibleDuplication": false,
  "checkSum": "md5hash",
  "roles": [ 1 ],
  "coordinate": "55.75,37.61"
}
            
## Пример успешного ответа (201):
{ "attachmentID": 123, "checkSum": "md5hash", "fileName": "photo.png", "isProtected": true }
            
## Негативные сценарии:
- 401 Unauthorized — отсутствует или некорректен Bearer-токен.
- 403 Forbidden — недостаточно прав `AttachmentUpload`.
- 400 — некорректный base64/empty file/checkSum.
- `POST /Attachments/upload/fromForm` — Загружает один файл из multipart/form-data. · коды: 201, 400
  ← body: { ContentLength?: int, ContentStream.CanRead?: bool, ContentStream.CanSeek?: bool, ContentStream.CanTimeout?: bool, ContentStream.CanWrite?: bool, ContentStream.Capacity?: int, ContentStream.Length?: int, ContentStream.Position?: int, ContentStream.ReadTimeout?: int, ContentStream.WriteTimeout?: int, ContentType?: str, Coordinate?: str, Description?: str, File: file, FileName?: str, IsIgnorePossibleDuplication?: bool, IsPublic?: bool, Md5Hash?: str, Roles?: int[], Uid?: uuid } → RAUploadResult
  Используется для загрузки одного вложения из HTML-формы.
            
## Пример запроса (multipart/form-data):
POST /attachments/upload/fromForm
Authorization: Bearer <token>
Content-Type: multipart/form-data
Поля: file=<binary>, description=<text>, isPublic=<true|false>, isIgnorePossibleDuplication=<true|false>, roles=<short[]>, coordinate=<string>
            
## Пример успешного ответа (201):
{ "attachmentID": 123, "checkSum": "md5hash", "fileName": "photo.png", "isProtected": false }
            
## Негативные сценарии:
- 401 Unauthorized — отсутствует или некорректен Bearer-токен.
- 403 Forbidden — недостаточно прав `AttachmentUpload`.
- 400 — некорректные входные данные/пустой файл/несоответствие формата.
- `POST /Attachments/v2/upload/fromForm` — Загружает несколько файлов из multipart/form-data. · коды: 201, 400
  ← body: { Attachments?: FromFormUploadData[] /* Данные загружаемого файла, полученные из формы */ } → RAUploadResult[]
  Используется для пакетной загрузки вложений из формы.
            
## Пример запроса:
POST /attachments/v2/upload/fromForm
Authorization: Bearer <token>
Body: { "attachments": [ { "file": <binary>, "fileName": "a.txt", "description": "..." , "isPublic": true, "roles": [ 1 ] } ] }
            
## Пример успешного ответа (201):

## Негативные сценарии:
- 401 Unauthorized — отсутствует или некорректен Bearer-токен.
- 403 Forbidden — недостаточно прав `AttachmentUpload`.
- 400 — некорректные данные.
- `GET /Attachments/{attachmentID}` — Возвращает временную ссылку для скачивания вложения. · коды: 200, 307, 400, 500
