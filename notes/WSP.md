# WSP — заметки практики

> **Что здесь:** проверенные практикой правила и грабли сервиса WSP (графики рабочего времени). Сигнатуры ручек — [endpoints/WSP.md](../endpoints/WSP.md).
> **Когда сюда идти:** перед чтением рабочих интервалов графика или расчётом сроков по графику.

## Грабли

⚠ `GET /WorkSchedules` — параметров в swagger нет, рабочие подобраны (2026-11-19, тенант 1): `scheduleRuleID` (обязателен: без него `400 «Не указан график работ»`), `validFrom`/`validTill` (`YYYY-MM-DD`) — фильтр по `dateWork`, **обе границы включительно**, время в фильтре игнорируется (`validFrom=…T12:00:00` утро того же дня не отрезал). Имена `dateFrom`/`from`/`period.from` фильтр НЕ включают — молча отдаётся вся история. Ответ — `{"<ID графика>": [{scheduleRuleID, timeFrom, timeTill, dateWork, isNightShift}]}`; повторённый `scheduleRuleID` отдаёт несколько графиков одним словарём.

⚠ `GET /WorkSchedules` без дат отдаёт **всю историю графика** до конца его периода (`GET /ScheduleRules/{id}` → `periods[].till`): у графика с 2020 г. — 1464 интервала, ~200 КБ, без усечения и без `Range`. За концом периода интервалов нет вовсе (2026-11-19, тенант 1).

⚠ Время интервалов (`timeFrom`/`timeTill`) — **без пояса**. Ночная смена — `timeTill` на следующие сутки при `dateWork` дня начала (`dateWork 2026-11-12`, `09:00` → `2026-11-13T08:59`), поэтому окно чтения для момента X начинают с дня **до** X. Круглосуточный день — `00:00–23:59` (не до полуночи) (2026-11-19, тенант 1).

⚠ `overridings` в `POST /ScheduleRules` день из графика **не убирают** (4 формы `ScheduleDto`, 2026-11-19, тенант 1): в выдаче `GET /WorkSchedules` появляются ДОПОЛНИТЕЛЬНЫЕ интервалы — круглосуточный, нулевой `00:00–00:00` или день, порезанный на смежные куски (`09–12`, `12–14`, `14–18`). Потребитель обязан сливать смежные и отбрасывать нулевые. Как задать нерабочий день через API — не найдено.

⚠ `considerPublicHolidays: true` ставит `holidayCalendarID 1`, но праздники берутся из календаря тенанта: у тенанта 1 он пуст (`GET /ScheduleRules/holiday?year=2026` → `{}`), и 1–8 января остаются рабочими. Как отдаётся праздничный день при заполненном календаре — не измерено (2026-11-19).

⚠ Штатный SLA ([notes/SLA.md](SLA.md)) применяет интервалы графика **по МСК**, а не по поясу адреса заявки (2026-11-19, тенант 1).
