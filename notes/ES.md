# ES — заметки практики

> **Что здесь:** проверенные практикой правила и грабли сервиса ES (объекты/оборудование, компании, контакты). Сигнатуры ручек — [endpoints/ES.md](../endpoints/ES.md).
> **Когда сюда идти:** перед работой с объектами через API.

## Грабли

⚠ `GET /Assets` принимает недокументированный query-параметр `contactID` — фильтрует объекты по привязанному контактному лицу (обратная сторона связки `AssetContacts`). Это единственный способ получить «объекты контакта» одним запросом: прямые ручки дают только объект → его контакты (`GET /Assets/{assetID}/contacts`), а фильтра `contactID` у списка объектов **нет в swagger** (его нет в авто-генерируемом [endpoints/ES.md](../endpoints/ES.md)). Параметр рабочий — подтверждено мейнтейнером 2026-07-14. При следующем обновлении сверить, не появился ли он в swagger (тогда заметку убрать). Аналог у заявок — `GET /Tasks ?contactID`, у договоров — `GET /ServiceContract ?contactID`.

⚠ Недокументированный `contactID` у `GET /Assets` (см. выше) работает и на `HEAD /Assets` — тотал приходит уже отфильтрованным (проверено 2026-07-15: `HEAD /ES/Assets?contactID=105` → `Content-Range: items=0-0/1` против `items=0-0/577953` без фильтра). Это удобный способ получить «сколько объектов у контакта» одним запросом без вычитки. В swagger у `HEAD /Assets` query-параметров не описано вообще — ни `contactID`, ни прочих.

⚠ `GET /Assets` не поддерживает `isDeleted` (в swagger параметра нет, проверено 2026-07-15) — в отличие от `GET /Tasks` и `GET /Contacts`. Отфильтровать мягко удалённые объекты на стороне сервера нечем; общее правило «всегда `isDeleted=false`» из [overview.md](../overview.md) к объектам неприменимо.

⚠ `POST /Assets` понимает `X-Concurrency-Stamp`: повтор с тем же стампом — `409` с эхом существующего объекта, второй не создаётся; одновременные отправки (3 пары) — один объект, проигравший может ответить раньше победителя; стамп удалённого объекта — `409` с эхом удалённого. **Ключ эха начинается с кириллической «с» (U+0441): `"сoncurrencyStamp"`** — так и в примере swagger; у `POST /WORK/Tasks` ключ латинский. Разбирать эхо надо с учётом обоих написаний (2026-09-25, тенант 1; 2026-10-16, тенант 192).

⚠ `PUT /Assets/{assetID}/publish`: повторная публикация (и вторая из двух одновременных) — `409 [{"code": "AlreadyDone", "message": "Операция была выполнена ранее"}]`, объект остаётся опубликованным. Хост-объект (`isHostable`) без локации — `409 InvalidOperation` «Хост-объект должен иметь локацию», и эта проверка идёт раньше проверки вида работ; без действующего вида работ — `409 InvalidOperation` «Объект должен иметь действующий вид работ». Оборудование под **неопубликованным** хостом без локации публикуется, если у него есть участок и вид работ (2026-10-16, 2026-10-22, тенант 192).

⚠ `POST /Assets` создаёт объект и без `locationID` (хост-объект тоже; публиковать его потом нельзя — см. выше). `PUT /Assets` с `addedWorkTypes`/`addedDistricts` повторять безопасно: второй такой же запрос — `202`, вид работ в объекте один (2026-10-16, 2026-10-22, тенант 192).

⚠ `POST /Locations` без координат локацию не создаёт — со слов мейнтейнера (2026-10-22), отдельным вызовом не проверено. Страну и часовой пояс локации с координатами сервер проставляет сам (2026-10-22, тенант 192).

⚠ Доп.поля объекта: v1 `POST /AssetAttributes` **заменяет набор доп.полей объекта целиком** — со слов мейнтейнера (2026-10-14); `POST /AssetAttributes/v2` пишет переданные поля и **перезаписывает** уже заполненные (по журналу исполнений интеграции, 2026-10-14, тенант 335), ответ — `202 []`. Пустое значение (`null` или `""`, `POST` или `PUT …/v2`) поле **не стирает**: строка поля остаётся с `""`/`null`. Стереть одно поле, не трогая остальные, — `DELETE /AssetAttributes` с телом `[{"assetID": …, "data": [{"attributeID": …}]}]` → `202 []`; повторное удаление уже отсутствующего поля — `409 [{"code": "AllItemsRejected", "message": "Все переданные записи невалидны"}]` (2026-11-11, тенант 192).

⚠ `PUT /Assets/{assetID}` без `locationID` в теле привязку объекта к локации **не сбрасывает** (две ТТ и одно оборудование, ~200 таких `PUT` за день — все `202`, локация на месте; 2026-11-12, тенант 192). Проверено только для `locationID`; сбрасываются ли другие пропущенные поля (`positionOnSchema`, флаги эскалации) — не измерено.

⚠ `GET /Assets/{assetID}` удалённого объекта — `409 [{"code": "AssetDeleted", "message": "Объект удалён: OperableAsset", …}]`, а не `200` с `deleted`. Заявка при этом продолжает ссылаться на объект: в `GET /WORK/Tasks/{taskID}` у `asset` заполнено `deleted` (по ответам интеграции, 2026-11-06, тенант 55). `path` детального чтения у объекта верхнего уровня — `[сам объект]`, не `[]`.

⚠ Детальное `GET /Assets/{assetID}` у оборудования **не отдаёт `parentID`**, хотя схема его объявляет, — только `parent {id, name, assetType}`; список `GET /Assets` `parentID` отдаёт. Координата локации — строка `"широта:долгота"` с 6 знаками и хвостовыми нулями (`"55.727100:37.679817"`), сравнивать числом (2026-10-15, тенант 192).

⚠ В элементах списка `GET /Assets` **нет `assetType`** — даже при фильтре по нескольким `assetTypeID` (повторённый параметр работает как ИЛИ). Тип узнаётся запросом с одним `assetTypeID` или детальным чтением. `startWithAssetID` отдаёт потомков **всех** уровней, не только детей (2026-11-11, тенант 55).

⚠ `GET /Assets/{assetID}/contacts` и `GET /Assets/{assetID}/districts` отдают **словарь** «ID → запись» (`{"7": {"name": …}}`), `id` — только в ключе (схема участка `id` не содержит); порядок ключей — не по возрастанию. Объект без контактов — `204`. `Content-Range` у контактов нет (2026-10-28, тенант 88; 2026-11-10, тенант 55).

⚠ `GET /Districts?assetID=` отдаёт участки объекта — те же, что `GET /Assets/{assetID}/districts` (30 объектов из 30, сравнение по именам); объекты с несколькими участками не встречались (2026-10-15, тенант 192).

⚠ `GET /Companies` без `Range` молча режет выдачу до **1000** — `200`, без `Content-Range`, признака неполноты нет (1440 компаний в тенанте). С `Range` пагинация доходит до хвоста. `GET /Companies/{id}` отдаёт поле `deleted` (2026-11-02, тенант 88). Порог у `GET /Assets` другой — 10000, см. [overview.md](../overview.md).

⚠ `GET /Assets/{assetID}/attributes` с `Range` — `206` даже тогда, когда окно накрыло всю коллекцию (`items=1-100` → `items=1-8/8`); без `Range` — `200` без `Content-Range` (2026-10-15, тенант 192).
