# COMMON — заметки практики

> **Что здесь:** проверенные практикой правила и грабли сервиса COMMON (контакты, справочники, вложения). Сигнатуры ручек — [endpoints/COMMON.md](../endpoints/COMMON.md).
> **Когда сюда идти:** перед работой с контактами и справочниками через API.

## Грабли

⚠ `HEAD /Contacts` → `404`: у контактов, в отличие от заявок (`HEAD /Tasks`), HEAD не реализован (проверено 2026-07-15; в swagger у `/Contacts` объявлены только `GET`/`POST`/`PUT`/`DELETE`). Узнать тотал без вычитки страницы нечем — брать его из `Content-Range` обычного `GET /Contacts` с заголовком `Range`.

⚠ `GET /Contacts ?searchText` ищет одновременно по **ФИО, телефону и email**, включая частичное совпадение (проверено 2026-07-15: `+77653434343` → 1 запись; `kolotyh` → 1 запись по `kolotyh@gmail.com`; `Иван` → 6 записей по ФИО). Поле `position` поиск **не** охватывает: `тестер` → 0 записей при существующем контакте с `position: "тестер"`. Отдельных параметров поиска по телефону/почте у ручки нет — они и не нужны.

⚠ `GET /Contacts` не поддерживает сортировку (`orderBy` в параметрах нет, в отличие от `GET /Tasks`) — порядок выдачи по `id` по возрастанию (проверено 2026-07-15: id 10, 21, 27, 40, 51, 52, 105, 106). Сортировать выдачу на клиенте постранично нельзя: отсортируется только текущая страница, а выглядеть будет как сортировка всего списка.

⚠ `GET /Attachments/{attachmentID}?noRedirect=true` → `200 {fileName, url, size, created}`; `url` ведёт на внешнее хранилище, открывается **без авторизации** и живёт **20 с** от выдачи, затем `401` — ссылку брать непосредственно перед передачей, не хранить. Без `noRedirect` — `307` (2026-10-12, 2026-11-11, тенант 192).

⚠ `POST /Attachments/upload/fromForm` → `201 {"attachmentID", "checkSum", "fileName", "isProtected"}`; `checkSum` — MD5 содержимого заглавным hex; имя файла (в том числе кириллица) сохраняется байт в байт. **`X-Concurrency-Stamp` ручка не понимает:** повтор с тем же стампом — снова `201` и второе вложение с тем же `checkSum` (оба раза с `IsIgnorePossibleDuplication=true`; без флага не проверялось). После `DELETE /Attachments/{attachmentID}` (`202`) чтение вложения — `409 [{"code": "AttachmentDeleted", "message": "Вложенный файл был удалён"}]` (2026-11-12, тенант 192).

⚠ `GET /Attributes` отдаёт и **удалённые** доп.поля (с заполненным `deleted`) — «ID находится» не значит «поле живо» (2026-10-06, тенант 291).

⚠ Формы значений доп.полей даты, как их пишет веб-интерфейс: «Дата» — полдень без пояса `YYYY-MM-DDT12:00:00`; «Дата и время» — момент в UTC с `Z` и миллисекундами (`2025-04-02T20:59:00.000Z` = 23:59 МСК), поэтому первые 10 символов такого значения — дата в UTC, а не местная. В одном поле «Дата» встречаются и чужие формы: голая дата `YYYY-MM-DD` (запись через API) и ISO с `Z` и произвольным временем (`applicationID: 1`) — читать надо все три (2026-10-22, тенант 192; 2026-10-26).
